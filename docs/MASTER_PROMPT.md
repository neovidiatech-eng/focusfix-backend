## 0) طريقة الاستخدام

1. حطّ نسخة من الملف في كل ريبو: `docs/MASTER_PROMPT.md`.
2. لو بتشتغل بـ AI agent: ابدأ كل جلسة بـ «اقرأ `docs/MASTER_PROMPT.md` كامل قبل أي تعديل»، وبعدها استخدم برومت الريبو من القسم 14.
3. أي بند عليه **[إلزامي]** مش قابل للتفاوض. الباقي افتراضات قوية: تتغير بس بسبب مكتوب في الـ PR.
4. **لا تخترع محتوى تجاري** (أسعار، سياسات، نصوص قانونية، أرقام إحصائية، آراء عملاء). استخدم Seed واضح الوسم `needs_review` وسيب القرار لصاحب المشروع.
5. لو في غموض يغيّر البنية (Schema / API / تدفق الحجز): اسأل قبل ما تبني. غير كده كمّل بأقرب افتراض لهذا الملف ووثّقه.

## 1) السياق والهدف

**FocusFix** منصة حجز صيانة أجهزة Apple (iPhone / iPad / Apple Watch، وMacBook لاحقاً) بخدمة منزلية في القاهرة والجيزة. الفني بيروح للعميل ويصلّح الجهاز قدامه.

**الهدف التجاري الأول:** تحويل زوار الحملات الإعلانية (Meta / Google) لحجوزات. صفحات الهبوط الأساسية للحملات: **الأسعار · الحجز · صفحات المناطق · المقالات**.

**ترتيب الأولويات (لما حاجتين تتعارض، الأعلى يكسب):**
1. UI/UX (الشكل والإحساس بالثقة)
2. السرعة والأداء
3. Responsive / Mobile-First (أغلب الزوار موبايل)
4. SEO
5. اتساق التصميم والكود
6. عدد الفيتشرز (نبدأ بالأساسيات، مش 100% من الـ SOW)

## 2) تحليل المنافس (ifixegy.com) — إيه اللي بنتعلمه وإيه اللي مش هنقلده

> **قاعدة [إلزامي]:** الاستيحاء وظيفي فقط. ممنوع نسخ نصوص أو صور أو ألوان أو تخطيط بصري أو كود. الهوية والنصوص والتصميم مستقلين تماماً.

| اللي موجود عندهم | المشكلة / الفرصة | قرارنا |
|---|---|---|
| صفحة حجز **واحدة طويلة**: صور كل الموديلات (~29) قبل الفورم | سكرول طويل، الفورم بعيد، تقيلة على الموبايل | Stepper من 4 خطوات، الموديلات بتتطوي بعد الاختيار، بحث + تجميع بالسلسلة |
| الحجز **من غير سعر** ومن غير اختيار موعد | العميل ما يعرفش التكلفة، والموعد بيتحدد بعدين بالتليفون | سعر لحظي + إجمالي تقديري + اختيار يوم وSlot |
| حقل «رابط موقع الموعد» (Google Maps) **إجباري** | احتكاك عالي: العميل لازم يجيب رابط ويلصقه | عنوان نصي + زر اختياري «استخدم موقعي الحالي» |
| اسم أول/أخير منفصلين + راديو «واتساب نفس الرقم؟» | حقول زيادة | حقل اسم واحد، وواتساب «نفس الرقم» مفعّل افتراضياً |
| **قائمة المناطق بمصاريف الانتقال** (مثال: 6 أكتوبر +150 ج.م) | فكرة ممتازة وشفافة | **نحتفظ بيها ونوسّعها**: الرسوم بتظهر في القائمة وفي الملخص والإجمالي، وبتتدار من الداشبورد (القسم 8.5 و9) |
| قائمة موديلات الحجز **ناقصة** (iPhone 17 و17 Air موجودين في الأسعار وغايبين من الحجز) | تضارب بين مصدرين | **مصدر واحد للحقيقة**: الحجز والأسعار بيقروا من نفس الجداول |
| جدول الأسعار: Pagination بـ JS (4 صفحات)، خلايا فاضية أو `-` أو `Not Available` أو `With screen` أو `8,500 (with home)`، أسماء مقطوعة (`6th g`)، عمود بطارية فاضي في الآيباد | صفوف مخفية عن جوجل، بيانات غير منتظمة | كل الصفوف في الـ HTML، **حالة مكتوبة لكل خلية** (متاح / غير متاح / مشمول / عند الطلب)، أسماء كاملة، وإخفاء الأعمدة الفاضية |
| الضمان جملة عامة (12 شهر شاشات / 6 بطاريات) | مش مرتبط بالبيانات | مدة الضمان **لكل خدمة من الـ DB** |
| مفيش زر حجز جنب كل سعر | فرصة تحويل ضايعة | زر «احجز» لكل صف بيفتح الحجز والموديل والخدمة متعبّيين |
| تقييمات جوجل بـ widget خارجي (Trustindex) | JS تقيل من طرف تالت | مكوّن داخلي خفيف: التقييم والعدد من الإعدادات + آراء منتقاة، وربط Places API في المرحلة 2 |
| Placeholders عربي داخل فورم إنجليزي | i18n ناقص | كل نص UI وكل رسالة خطأ بلغتين |
| خريطة Embed دايماً في الفوتر | تحميل بدون لزوم | Click-to-load (صورة ثابتة + زر) |

## 3) القرارات المقفولة

**الريبوهات [إلزامي]:** ثلاثة ريبوهات مستقلة على GitHub، كل واحد له فريق:
`focusfix-web` · `focusfix-admin` · `focusfix-api`
(الكود الحالي Next.js 15 يتحول لـ `focusfix-web`، وصفحة الداشبورد اللي جواه تتشال وتتبني في `focusfix-admin`.)

| الطبقة | التقنية |
|---|---|
| Web | Next.js 15 (App Router) · TypeScript strict · Tailwind · shadcn/ui (Radix) · `next-intl` · React Hook Form + Zod |
| Admin | React + Vite SPA · React Router · TanStack Query / Table / Virtual · shadcn/ui · TipTap · Recharts · dnd-kit |
| API | Node (أحدث LTS) · Express · TypeScript · Prisma · PostgreSQL · Redis · BullMQ · Zod · Pino |
| خدمات | Cloudflare R2 (صور) · Resend أو SendGrid (إيميل) · Cloudflare Turnstile (anti-spam) · GTM + GA4 + Meta Pixel |
| أدوات | pnpm · GitHub Actions · Docker · Sentry · Lighthouse CI |

**قرارات المنتج:**
- اللغات: عربي RTL (افتراضي) + إنجليزي، مسارات `/ar` و`/en` دايماً. الداشبورد عربي RTL (جاهز للترجمة).
- العملة: جنيه مصري، أرقام لاتينية `0-9` في الأسعار والتواريخ (`Intl.NumberFormat('ar-EG-u-nu-latn')`)، والعرض «22,000 ج.م».
- الـ Slugs **لاتينية دايماً** (حتى في العربي) لأن الروابط العربية بتتحول لـ `%D8...` في واتساب.
- الحجز: **4 خطوات** (ملحق على الـ SOW اللي كان 5)، **من غير OTP** في المرحلة 1 (بدله Turnstile + Rate Limit)، **الإيميل إجباري**.
- الدفع: كاش/محفظة عند الفني. مفيش دفع أونلاين الآن.
- الأدوار: دور واحد (Super Admin) الآن، لكن الـ Schema والـ Middleware جاهزين لـ RBAC.
- المراجعة القانونية: الخصوصية والشروط نصوصها من صاحب المشروع. قانون حماية البيانات الشخصية المصري (151 لسنة 2020) لازم يتراجع مع مستشار قانوني قبل الإطلاق.

## 4) المبادئ الحاكمة (non-negotiables)

1. **[إلزامي] لا Hardcoding لمحتوى تشغيلي:** أسعار، خدمات، موديلات، مناطق ورسومها، مقالات، FAQ، أرقام التواصل، نصوص الصفحات، أكواد التتبع — كلها من الـ API وتتدار من الداشبورد. الملفات `messages/*.json` للنصوص الثابتة للواجهة فقط (أزرار، labels، أخطاء).
2. **[إلزامي] مصدر واحد للحقيقة:** أي رقم أو اسم ظاهر في مكانين لازم يتقرأ من نفس الجدول.
3. **[إلزامي] ثنائي اللغة من أول يوم:** `name_ar / name_en` في كل حقل ظاهر للعميل، وكل رسالة خطأ بلغتين.
4. **[إلزامي] Mobile-First:** التصميم والاختبار يبدأوا من عرض 360px.
5. **[إلزامي] Server Components افتراضياً.** `"use client"` بس للتفاعل الفعلي (الحجز، البحث، القوائم).
6. **[إلزامي]** كل مكوّن بيعرض داتا له 4 حالات: Loading (Skeleton بدون Layout Shift) · Empty · Error (مع إعادة المحاولة) · Success.
7. **[إلزامي] Accessibility:** WCAG AA، تنقل بالكيبورد، Focus واضح، `label` لكل حقل، رسائل الخطأ مربوطة بالحقل (`aria-describedby`).
8. **[إلزامي] لا Layout Shift:** أبعاد محددة للصور، وخطوط بـ `font-display: swap` مع `size-adjust`.
9. **[إلزامي] Types من العقد:** الواجهات مش بتكتب Types يدوي لردود الـ API، بتتولد من OpenAPI.
10. **[إلزامي] الأمان:** Zod على كل مدخل، Parameterized queries فقط (Prisma، لا Raw SQL)، تعقيم أي HTML، ولا أسرار في الكود أو الـ Git.

## 5) المعمارية والعقد بين الريبوهات

**5.1 الـ API هو مصدر الحقيقة**
- `focusfix-api` يولّد `openapi.json` تلقائياً من Zod (`zod-to-openapi`) ويعرضه على `/api/v1/openapi.json` + Swagger UI على `/api/docs`.
- `focusfix-web` و`focusfix-admin` عندهم سكريبت `pnpm gen:api` (`openapi-typescript` + `openapi-fetch`) بيسحب العقد من Staging. الـ CI بيفشل لو الـ Types القديمة مش متوافقة.
- التغييرات: إضافة فقط داخل `/api/v1`. أي تغيير كاسر يتعمل `/api/v2`.
- Mock Server (Prism أو MSW) من `openapi.json` عشان الفرونت ما يستناش الباك.

**5.2 الـ Design Tokens**
حزمة خاصة صغيرة `@focusfix/design-tokens` (CSS variables + Tailwind preset: ألوان، خطوط، spacing، radii، shadows) تتنشر على GitHub Packages ويستخدمها الموقع والداشبورد. أي لون أو حجم خط خارج الـ tokens مرفوض في الـ PR.

**5.3 الكاش وإعادة التوليد (Web ⇄ API)**
- في Next 15 الـ `fetch` **مش بيتكاش افتراضياً**: حدّد `next: { revalidate, tags }` صراحةً لكل طلب.
- الـ Tags: `prices` · `catalog` · `areas` · `blog` · `blog:{slug}` · `content` · `faqs` · `settings`.
- بعد أي تعديل من الداشبورد، الـ API ينادي `POST {WEB_URL}/api/revalidate` بـ header سري `x-revalidate-secret` وbody `{ "tags": [...], "paths": [...] }`. التغيير لازم يظهر في الموقع خلال ثواني.
- الـ API: Redis cache للقوائم العامة (TTL 5 دقايق + مسح عند التعديل) وـ ETag.

**5.4 البيئات والنطاقات**
`local` · `staging` (`noindex` + Basic Auth) · `production`. الدومينات تحت نفس الـ registrable domain فكوكي الـ refresh (`HttpOnly`, `Secure`, `SameSite=Strict`) تشتغل. متغيرات البيئة موثقة في `.env.example` في كل ريبو (أسماء بس).

**5.5 هيكل كل ريبو**
```
focusfix-web/
  src/app/[locale]/(site)/...        # الصفحات
  src/app/api/revalidate/route.ts
  src/features/{home,prices,booking,areas,blog,contact}/
  src/shared/{ui,lib,hooks}/
  src/lib/api/                       # العميل المولّد من OpenAPI
  messages/{ar,en}.json              # نصوص الواجهة الثابتة فقط

focusfix-admin/
  src/{routes,features,shared,lib/api}/

focusfix-api/
  src/modules/<name>/{routes,controller,service,repository,schemas,tests}/
  prisma/{schema.prisma,migrations,seed.ts}
  src/jobs/ (BullMQ)  src/lib/ (email, r2, redis, openapi)
```

## 6) الـ Design System
- الهوية البصرية: مقترحين للاتجاه البصري في M0، بدون برتقالي/أسود (تميزاً عن المنافس).
- ألوان دلالية: `brand`, `brand-contrast`, `surface`, `surface-alt`, `text`, `text-muted`, `border`, `success`, `warning`, `danger`, `info`.
- خطوط: عائلة عربية أولاً (مثل Cairo أو IBM Plex Sans Arabic).
- RTL كامل باستخدام Tailwind Logical Properties.

## 7) نطاق المرحلة الأولى (MVP)
- **الموقع:** رئيسية · خدمات · أسعار · حجز (4 خطوات بدون OTP) + صفحة نجاح · مناطق · مدونة · تواصل · سياسة الضمان (محتوى) · شروط وخصوصية.
- **الداشبورد:** نظرة عامة وكروت KPIs · الحجوزات · مصفوفة الأسعار الشاملة · الكتالوج · المناطق والمواعيد ورسوم الانتقال · المدونة المتقدمة (TipTap) · الرسائل والطلبات · المحتوى والإعدادات.
- **الباك اند:** Modular Monolith Node.js/Express + Prisma + PostgreSQL + Redis + BullMQ + Zod + OpenAPI + نظام البريد الإلكتروني.
